~/answer-grader grades scanned handwritten exam PDFs against a TOML key. Phone only scans, laptop does everything offline; must run on any laptop (Win/Mac/Linux), so no Apple-only APIs.

Stack (since 2026-09-27): pypdfium2 render → ink threshold (removes show-through) → PaddleOCR-VL-1.5 "Spotting:" (literal lines + boxes, rows() merges same-row items) → label parsing (bare "21.", "Q21", circled ①) → MCQ/short gaps filled from a second "OCR:" pass (never long answers: OCR mode renumbers lists) → exact match for MCQ/short, Gemma 4 E2B judge (score 0-4 from first-token probabilities, calibrated per model in grade.JUDGES) for written answers; unnumbered/misread answers placed by the question's wording. Anything uncertain = REVIEW. UI: app.py + static/ (see Git line).

Gotcha: PaddleOCR-VL ships use_cache=False → 15 min/page; pass use_cache=True (6-16 s/page on M4). LightOnOCR needs its own class + fp32 on MPS.

Benchmark: Anna University dataset (doi:10.17632/sf3kvjwknt.1, CC BY 4.0) in data/anna, eval_anna.py compares with teacher marks (OCR cached per task in data/ocr); ocr_bakeoff.py compares OCR engines.

Results on all 50 scripts: TrOCR pipeline read 36% of MCQs and found 34% of short answers; PaddleOCR-VL two-pass reads 83% of MCQs (unflagged MCQ marks 97% match teacher) and finds 91% of written answers (after the loop fix and wording-based placement).

Git: ~/answer-grader, tags v1 (similarity grading), v2 (Gemma judge), v3 (2026-09-28, every CHECKLIST.md item done, no git remote): stdlib web app (app.py + store.py SQLite, scrypt passwords, sessions, teacher/student roles, job queue, Host allow-list vs DNS rebinding; static/ SPA styled as a mark register; report cards; --store DIR), wording-based answer placement (91% of written answers found), handwritten test set + typed benchmarks (testset.py, eval_testset.py, judge_sets.py), CHECKLIST.md plan.

Gotchas found: PaddleOCR-VL loops on repeated patterns ("0,6 * 0,6 ...") and loses the page -> no_repeat_ngram_size=30; MPS allocator caches a buffer per input size -> torch.mps.empty_cache() after each page/answer (else 13 GB swap, disk nearly full); judge uses logits_to_keep=1; "Q16 2^n" labels; copied-question rule only drops lines adding <=1 new word.

Judge experiments (2026-09-28, Anna held-out, error/answer): current 0.46; yes/no per key point much worse (Gemma says "no" to nearly all); 5 teacher-marked examples in prompt 0.43 (within noise, not built); marking-scheme phrase rules (key points [text, marks, [phrases]], `marks` caps any-of lists; commit a3dc677, data/anna_scheme.toml) help on the same key (0.50->0.45) but end to end are a wash (total 4.2 vs 4.1) because the judge marks split points worse. Root problem: judge scores bunch near 2/4 so tiny calibration/key changes swing marks; Anna teacher marks are noisy (2 for garbled text). Remaining lever: the user's own marks for calibration, and answer placement/OCR.
